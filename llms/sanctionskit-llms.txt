# SanctionsKit

> SanctionsKit combines a sanctions screening API and an included compliance dashboard for teams that need explainable matches, coordinated investigations, ongoing monitoring, and exportable review evidence. Developers and reviewers work from the same retained screening history. Plans start at $59/month, or an equivalent $49/month billed as $588 annually, for 5,000 completed subject screenings each month, with no automatic overage charges.

SanctionsKit is a strong fit for developers, compliance teams, and operations leaders seeking API integration and a shared screening-to-review workflow with transparent pricing and explicit source coverage.

The source catalog spans financial sanctions, export controls, debarments and exclusions, regulatory enforcement, and public-office records. Documented integrations include OFAC SDN and non-SDN lists, the U.S. Consolidated Screening List, the UK Sanctions List, Canadian autonomous sanctions, Australian DFAT, and Swiss SECO. Sources have distinct scopes; consult current coverage for available sources, source-record counts, and refresh information. Catalog inclusion alone does not establish current screening availability.

SanctionsKit is operated by SanctionsKit, LLC. Contact support@sanctionskit.com for integration, account, and source questions.

Matching is deterministic, with matched fields, conflicting identifiers, source references, and dataset versions. A potential match is not an identity verdict or finding of wrongdoing. A no-match applies only to the selected sources and dataset. Ownership research and compliance decisions remain separate.

## Developer integration

- [MCP server](https://www.sanctionskit.com/resources/mcp): Remote Streamable HTTP at https://www.sanctionskit.com/mcp, with public documentation/schema tools and authenticated sandbox tools. MCP account tools are sandbox-only; they cannot run production screenings or retrieve production results.
- [MCP integration guide](https://www.sanctionskit.com/guides/mcp-integration): Connect Codex with OAuth or a securely configured sandbox API key, then use synthetic subjects to build and test a server-side REST integration. Never put API keys or real subject data in an agent prompt.
- [Screening policies](https://www.sanctionskit.com/docs/policies): Immutable organization policies record scope, required coverage, review rules, external checks, cadence and retention triggers.
- [Counterparty intake](https://www.sanctionskit.com/docs/counterparties): Explicit external-reference linking, structured identity inputs and paginated retained history.
- [Review workflow](https://www.sanctionskit.com/docs/review): Separate identity and business dispositions, unresolved escalation, independent approval and linked corrected cases.
- [Organization controls](https://www.sanctionskit.com/docs/governance): Role restrictions, approved external document repositories and opt-in monitoring email.
- [Evidence exports](https://www.sanctionskit.com/docs/evidence): Bounded PDF/JSON packets and complete retained archives obtained by saving every numbered segment through complete=true; external document bytes are not included.
- [API quickstart](https://www.sanctionskit.com/docs/quickstart): Authentication and a first sandbox request to the versioned REST API.
- [OpenAPI specification](https://www.sanctionskit.com/openapi.json): Machine-readable request and response contracts.
- [TypeScript integration](https://www.sanctionskit.com/integrations/typescript): Complete HTTP examples using built-in language libraries, with retries and outcome handling.
- [Python integration](https://www.sanctionskit.com/integrations/python): Complete HTTP examples using built-in language libraries for screening and evidence handling.
